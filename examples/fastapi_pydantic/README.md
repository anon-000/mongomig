# Example: FastAPI + Pydantic + PyMongo

A FastAPI service using plain Pydantic models and PyMongo's async client. MongoMig manages
the schema.

```text
userservice/models.py      Pydantic models registered with @collection
userservice/main.py        FastAPI app; applies migrations on startup (dev)
migrations/env.py          imports the models; storage="python" (model_dump())
migrations/versions/       two autogenerated revisions: initial schema, add role and phone
mongomig.yaml
```

## Try it

```bash
pip install -r requirements.txt
docker compose -f ../../docker-compose.yml up -d --wait     # or any MongoDB 6+
export MONGODB_URI="mongodb://localhost:27017/?directConnection=true"

mongomig plan          # what would run, with estimates
mongomig upgrade       # create collections, indexes, validator; backfill role
mongomig current

uvicorn userservice.main:app --reload
curl -X POST localhost:8000/users -H 'content-type: application/json' \
     -d '{"name": "Auro", "email": "auro@example.com"}'
```

## Change the schema

1. Edit `userservice/models.py`, e.g. add `nickname: str = ""` to `User`.
2. `mongomig diff` shows the change, classified: a new required field with a default means
   the existing documents are backfilled.
3. `mongomig revision --autogenerate -m "add nickname"` generates the migration.
4. Review the file, commit it together with `migrations/schema_snapshot.json`.
5. In CI: `mongomig validate` (fails if a model change has no migration).
6. Deploy: `mongomig upgrade`.
